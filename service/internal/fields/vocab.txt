# Sous Chef merchant vocabulary: what merchants call things that the
# editor's labels and keys call something else.
#
# Read at query time by internal/fields (the candidate-fields block) and by
# internal/prompt (the "Also called" lines of the system[1] index).
# docs/VOCABULARY.md says when to add a line. One entry per line; '#'
# starts a comment: say WHY the line exists (the request that needed it).
#
#   merchant words = editor words[, editor words …]
#     A TERM. Wherever the merchant's text says the left side, the retrieval
#     also reads each right side, at 0.8 of a written word's weight; the
#     written words stay. Write editor words that occur in field LABELS or
#     KEYS: "rounder = radius" finds every *Radius field, including the ones
#     added after this line. Words compare lower-cased and singular, after
#     the spelling folds of tokens.go (colour→color, bg→background,
#     btn→button, pic/photo/picture→image). A stop word on the left (to, on,
#     the, my …) must be in the text as written ("turn on"). Any other stop
#     word in the text is skipped, so "rename site" matches "rename my site".
#
#   @<kind>:<id> = phrase, phrase …
#     A CONTAINER ALIAS: phrases that NAME a section type (s:<type>), a
#     global panel (g:<Panel>), branding (b:branding) or a page (p:<page>),
#     besides the words of its id. A named target goes to the top of the
#     block, so keep these few and unambiguous: never a word or label that
#     another container also has. The prompt index prints the first three
#     (in this order) that its id does not already say. "page:<slug>" means
#     the container counts as named while the merchant views that page.
